1. Branch prediction and the idea behind TAGE

A pipelined processor fetches instructions before it knows whether a conditional branch will be taken. A branch predictor guesses the outcome at fetch time. A wrong guess (mispredict) costs a pipeline flush, so fewer mispredicts means a faster processor.

Simple predictors

  • Bimodal: a table of 2-bit saturating counters indexed by the branch address (PC). The counter moves up when the branch is taken and down when it is not; its top bit is the prediction. It learns branches that are mostly taken or mostly not taken.
  • gshare: indexes the counter table with PC XOR global history. The global history register (GHR) is a shift register holding the outcomes of the last branches. gshare can learn patterns, but only within its history length (12–13 bits here).

TAGE (TAgged GEometric history length)

TAGE combines several tables that look at different amounts of history, with the lengths growing geometrically (here 4, 8, 16 and 32 outcomes):

  • A base table T0 (bimodal) always gives a prediction.
  • Each tagged table T1..T4 is indexed by a hash of the PC and its own history length. Every entry stores a tag, so a table only answers if the entry really belongs to this branch and history (a hit).
  • The prediction comes from the hitting table with the longest history (the provider). Short histories learn quickly; long histories catch correlations far back.
  • Entries are allocated in longer-history tables only when a branch is mispredicted, and a useful bit u protects entries that have proven themselves.
Why it matters here: on a branch whose outcome depends on a branch 16 or 32 branches earlier, our TAGE mispredicts 0.05–0.13 % of the time, while gshare with the same storage mispredicts about 50 % (it cannot see that far back). See section 8.

2. Architecture overview

The core (tage_top) has two independent paths:

  • Predict (combinational): pred_pc goes through the hash, the five tables are read through their read-only port B, and tage_predict picks the provider. The result is pred plus a metadata bundle pred_meta.
  • Update (on the clock edge): the saved metadata, the PC and the real outcome go into tage_update. Through port A it reads the current entries at the saved indices, computes the new values and writes them back on the clock edge. The GHR shifts on the same edge.

3. Data formats and the life of one branch

Tagged table entry

  • valid: the entry has been allocated. Without it, an empty entry whose stored tag happened to match would give a false hit.
  • tag: identifies which branch/history the entry belongs to.
  • ctr: 3-bit saturating counter; values 4..7 predict taken, 0..3 not taken. New entries start at the weakest value on the correct side (100 for taken, 011 for not taken).
  • u: "useful" bit, set when this entry was right and the alternate would have been wrong. Entries with u = 1 are not replaced.

The base table entry is just a 2-bit counter (values 2, 3 predict taken).

Metadata carried from predict to update

rtl/tage_pkg.sv — tage_meta_t (lines 36–43)
  36    typedef struct packed {
  37      logic [PROV_W-1:0]         prov;      // provider table (0 = base)
  38      logic [PROV_W-1:0]         alt;       // alternate table (0 = base)
  39      logic [NUM_T:1][IDX_W-1:0] idx;       // index used in each tagged table
  40      logic [NUM_T:1][TAG_W-1:0] tag;       // tag computed for each tagged table
  41      logic                      pred;      // final prediction
  42      logic                      alt_pred;  // alternate prediction
  43    } tage_meta_t;

The update uses these saved values instead of recomputing the hashes. That keeps the update exact even though the GHR is about to change, and the update logic needs no hash circuit of its own.

The life of one branch (2 clock cycles)

CycleWhat happens
A — predictPC is applied. Hash, table read (port B), tag compare and provider selection all happen combinationally. At the end of the cycle the board registers pred, pred_meta, the PC and the actual outcome.
B — updateupd_en = 1 with the registered values. Port A reads the entries at meta.idx; tage_update computes new values; on the clock edge the tables are written and the GHR shifts in the outcome. The mispredict counters count.

Only one branch is in flight at a time, so the next prediction always sees a fully updated predictor (no speculative history is needed).

4. The predictor core, module by module

4.1 tage_pkg — parameters and xor_fold

rtl/tage_pkg.sv (lines 44–56)
  44  
  45    // XOR-fold the low `len` bits of h into IDX_W bits. Bit b of the slice lands
  46    // in bit (b mod IDX_W) of the result, which is identical to XORing IDX_W-bit
  47    // chunks with the last chunk zero-padded.
  48    function automatic logic [IDX_W-1:0] xor_fold(input logic [GHR_W-1:0] h,
  49                                                  input int unsigned       len);
  50      logic [IDX_W-1:0] f;
  51      f = '0;
  52      for (int unsigned b = 0; b < GHR_W; b++) begin
  53        if (b < len) f[b % IDX_W] = f[b % IDX_W] ^ h[b];
  54      end
  55      return f;
  56    endfunction

What xor_fold does: a table index is only 8 bits, but the history may be up to 32 bits. The history is cut into 8-bit chunks that are XORed together (the last chunk is zero-padded). The loop does this bit by bit: history bit b is XORed into result bit b mod 8. Because len is a constant for each table, synthesis turns the loop into a small XOR tree (at most four inputs per output bit).

Example: xor_fold(0x1234_5678, 32) = 0x78 ^ 0x56 ^ 0x34 ^ 0x12 = 0x08; xor_fold(0xFFFF_FFFF, 4) = 0x0F (only 4 history bits are used).

  • Line 47: (* ram_style = "distributed" *) tells Vivado to build the array from LUT-RAM. Block RAM is not possible because the spec requires a combinational read, and BRAM can only be read synchronously.
  • Lines 51–53: one synchronous write port. Lines 55–56: two asynchronous read ports. This is exactly what an Artix-7 dual-port distributed RAM (RAM64X1D / RAM128X1D) provides: port A = read/write, port B = read only.
  • Generate block (lines 58–77): the same module serves as a tagged table (packs {valid, tag, ctr, u}) or, with TAG_W = 0, as the base table (only the counter is stored; valid reads as 1, u as 0).
  • There is no reset: LUTRAM cannot be reset in hardware. Initialisation is done by the sweep in tage_top (section 4.6).

4.3 tage_hash — global history and hashing

rtl/tage_hash.sv (lines 31–43)
  31    always_ff @(posedge clk) begin
  32      if (rst)         ghr <= '0;
  33      else if (upd_en) ghr <= {ghr[GHR_W-2:0], upd_taken};
  34    end
  35  
  36    always_comb begin
  37      logic [IDX_W-1:0] f;
  38      for (int i = 1; i <= NUM_T; i++) begin
  39        f      = xor_fold(ghr, int'(HIST_LEN[i]));
  40        idx[i] = pc[IDX_W+1:2] ^ f;
  41        tag[i] = pc[IDX_W+TAG_W+1:IDX_W+2] ^ {f[IDX_W-2:0], f[IDX_W-1]};
  42      end
  43    end
  • Lines 31–34: the GHR. On reset it becomes 0. On every update the new outcome is shifted in at bit 0 (so bit 0 is always the newest outcome, bit 31 the oldest).
  • Lines 36–43: for each table i, fold its history slice into f, then idx = pc[9:2] ^ f and tag = pc[17:10] ^ {f[6:0], f[7]}.
  • pc[1:0] is skipped because instructions are word aligned.
  • The tag uses a rotated copy of f, so the tag and the index are not the same function of history. Two histories that collide on the index are then likely to differ in the tag.

4.4 tage_predict — finding the provider

rtl/tage_predict.sv (lines 28–67)
  28    logic [NUM_T:1]    hit;
  29    logic [PROV_W-1:0] prov, alt;
  30    logic              prov_pred, alt_pred;
  31  
  32    always_comb begin
  33      for (int i = 1; i <= NUM_T; i++) hit[i] = t_valid[i] && (t_tag[i] == tag[i]);
  34    end
  35  
  36    // Scanning upward: each hit demotes the current provider to alternate.
  37    always_comb begin
  38      prov = '0;
  39      alt  = '0;
  40      for (int i = 1; i <= NUM_T; i++) begin
  41        if (hit[i]) begin
  42          alt  = prov;
  43          prov = PROV_W'(i);
  44        end
  45      end
  46    end
  47  
  48    always_comb begin
  49      prov_pred = base_ctr[BASE_CTR_W-1];
  50      alt_pred  = base_ctr[BASE_CTR_W-1];
  51      for (int i = 1; i <= NUM_T; i++) begin
  52        if (prov == PROV_W'(i)) prov_pred = t_ctr[i][CTR_W-1];
  53        if (alt  == PROV_W'(i)) alt_pred  = t_ctr[i][CTR_W-1];
  54      end
  55    end
  56  
  57    assign pred = prov_pred;
  58  
  59    always_comb begin
  60      meta.prov     = prov;
  61      meta.alt      = alt;
  62      meta.idx      = idx;
  63      meta.tag      = tag;
  64      meta.pred     = prov_pred;
  65      meta.alt_pred = alt_pred;
  66    end
  67
  • Lines 32–35: a table hits if its entry is valid and the stored tag equals the computed tag.
  • Lines 37–46: the loop goes from T1 up to T4. Each time a table hits, the previous provider becomes the alternate and this table becomes the provider. At the end, prov is the highest hitting table and alt the second highest (0 means the base table).
  • Lines 48–55: the predictions are the MSB of the selected counter: bit 2 of a 3-bit tagged counter, or bit 1 of the 2-bit base counter.
  • Lines 59–66: everything the update will need is packed into meta.
  • The alternate prediction is not the output; it is only needed for the u-bit rule (rule 2).

4.5 tage_update — the learning rules

rtl/tage_update.sv (lines 40–106)
  40    function automatic logic [CTR_W-1:0] sat_tag(input logic [CTR_W-1:0] c, input logic t);
  41      if (t) return (&c)       ? c : c + 1'b1;
  42      else   return (c == '0)  ? c : c - 1'b1;
  43    endfunction
  44  
  45    function automatic logic [BASE_CTR_W-1:0] sat_base(input logic [BASE_CTR_W-1:0] c, input logic t);
  46      if (t) return (&c)       ? c : c + 1'b1;
  47      else   return (c == '0)  ? c : c - 1'b1;
  48    endfunction
  49  
  50    logic              mispred, set_u, any_free;
  51    logic [NUM_T:1]    above, free;
  52    logic [PROV_W-1:0] alloc;
  53  
  54    always_comb begin
  55      mispred = (meta.pred != taken);
  56      set_u   = (meta.pred == taken) && (meta.alt_pred != taken);
  57  
  58      for (int i = 1; i <= NUM_T; i++) begin
  59        above[i] = (PROV_W'(i) > meta.prov);
  60        free[i]  = above[i] && !r_u[i];
  61      end
  62      any_free = |free;
  63  
  64      // smallest free table
  65      alloc = '0;
  66      for (int i = NUM_T; i >= 1; i--) begin
  67        if (free[i]) alloc = PROV_W'(i);
  68      end
  69    end
  70  
  71    always_comb begin
  72      base_we   = upd_en && (meta.prov == '0);
  73      base_wctr = sat_base(base_ctr, taken);
  74  
  75      for (int i = 1; i <= NUM_T; i++) begin
  76        // default: write back what is stored
  77        we[i]      = 1'b0;
  78        w_valid[i] = r_valid[i];
  79        w_tag[i]   = r_tag[i];
  80        w_ctr[i]   = r_ctr[i];
  81        w_u[i]     = r_u[i];
  82  
  83        if (upd_en) begin
  84          if (meta.prov == PROV_W'(i)) begin
  85            // rules 1 + 2 on the provider entry
  86            we[i]    = 1'b1;
  87            w_ctr[i] = sat_tag(r_ctr[i], taken);
  88            if (set_u) w_u[i] = 1'b1;
  89          end else if (mispred && above[i]) begin
  90            // rule 3 on the longer-history tables
  91            if (any_free) begin
  92              if (alloc == PROV_W'(i)) begin
  93                we[i]      = 1'b1;
  94                w_valid[i] = 1'b1;
  95                w_tag[i]   = meta.tag[i];
  96                w_ctr[i]   = taken ? ALLOC_CTR_T : ALLOC_CTR_NT;
  97                w_u[i]     = 1'b0;
  98              end
  99            end else begin
 100              we[i]  = 1'b1;
 101              w_u[i] = 1'b0;
 102            end
 103          end
 104        end
 105      end
 106    end

How the code implements the three rules:

RuleConditionEffectCode
1 Counteralwaysprovider counter +1/−1, saturating at 0..7; if there is no provider, the base counter +1/−1, saturating at 0..3sat_tag, sat_base, base_we
2 Usefulprovider > 0, prediction correct, alternate wrongprovider u = 1set_u
3 Allocateprediction wrong and provider < 4if a longer table has u = 0 at its index: write a new entry in the smallest such table. Otherwise clear u in all longer tables, so a slot frees up later. above, free, alloc, any_free
  • Default write-back: each table output starts as "write back what was read". Only the fields a rule changes are overwritten, so for example u-clearing keeps valid, tag and ctr unchanged.
  • "Smallest free table": the loop runs from T4 down to T1 and overwrites alloc on every free table, so the last assignment, the smallest index, wins. This is a simple priority encoder.
  • No conflicts: the provider table is written by rules 1/2, and only tables above the provider are written by rule 3. So each table receives at most one write per update.
  • When the provider is T4 there is no longer table, so rule 3 does nothing (the above mask is empty).

4.6 tage_top — wiring and the reset sweep

rtl/tage_top.sv — reset sweep (lines 41–57)
  41    logic [BASE_IDX_W-1:0] init_cnt;
  42    logic                  init_busy;
  43  
  44    always_ff @(posedge clk) begin
  45      if (rst) begin
  46        init_cnt  <= '0;
  47        init_busy <= 1'b1;
  48      end else if (init_busy) begin
  49        init_cnt <= init_cnt + 1'b1;
  50        if (&init_cnt) init_busy <= 1'b0;
  51      end
  52    end
  53  
  54    assign ready = ~init_busy;
  55  
  56    logic upd_go;
  57    assign upd_go = upd_en & ~init_busy;

LUTRAM cannot be reset, so after rst a 10-bit counter walks through all 1024 addresses. For those 1024 cycles every table is written with its power-on value: tagged entries get valid=0, u=0, ctr=011, base counters get 01. The tagged tables only have 256 entries, so they are simply written four times. While the sweep runs, ready is 0 and upd_go blocks any update. After a reset the predictor is therefore in exactly the same state as after power-on, and runs are reproducible.

gshare uses the same ideas in a smaller form: one counter table indexed by pc ^ ghr, the same kind of reset sweep (2K cycles), and the same 2-bit counter update. The tests use K = 12 (4K entries) and K = 13 (8K entries); the board uses K = 13 so both predictors have roughly the same storage.

5. The board wrapper (Nexys A7)

nexys7_top turns the predictor into a self-contained demo. No processor is needed: a hardware trace generator produces branches, TAGE and gshare predict them, and the mispredict counts appear on the 7-segment display.

rtl/board/nexys7_top.sv — run control FSM (lines 101–140)
 101    always_ff @(posedge clk) begin
 102      if (rst) begin
 103        state    <= S_IDLE;
 104        soft_rst <= 1'b0;
 105        mode_q   <= 2'd0;

 107        p_gs     <= 1'b0;
 108        p_taken  <= 1'b0;
 109        p_pc     <= '0;
 110        p_meta   <= '0;

 114          S_IDLE, S_DONE: begin
 115            if (start) begin
 116              soft_rst <= 1'b1;
 117              mode_q   <= sw_s2;
 118              state    <= S_INIT;
 119            end
 120          end
 121          S_INIT: begin
 122            if (!soft_rst && tage_ready && gs_ready && tg_valid) state <= S_PRED;
 123          end
 124          S_PRED: begin
 125            if (done) begin
 126              state <= S_DONE;
 127            end else begin
 128              p_tage  <= tage_pred;
 129              p_meta  <= tage_meta;
 130              p_gs    <= gs_pred;
 131              p_pc    <= tg_pc;
 132              p_taken <= tg_taken;
 133              state   <= S_UPD;
 134            end
 135          end
 136          S_UPD:   state <= S_PRED;
 137          default: state <= S_IDLE;
 138        endcase
 139      end
 140    end
  • S_IDLE / S_DONE: wait for BTNC. On a press, latch SW[1:0] as the trace mode and pulse soft_rst. That re-initialises the predictors, the trace generator and the counters, so every run starts from the power-on state and gives the same numbers.
  • S_INIT: wait until both predictors have finished their reset sweep.
  • S_PRED (cycle A): register the TAGE prediction, metadata, gshare prediction, PC and outcome.
  • S_UPD (cycle B): in_upd = 1 drives the update of both predictors, the counters and the trace generator. After 40 000 branches done stops the run.

6. Worked example: how TAGE learns a correlation gshare cannot see

Trace corr_d16 repeats a group of 17 branches: branch A (random), 15 always-taken filler branches, then branch B with the same outcome as A. When B is predicted, its outcome is in GHR bit 15 (16 branches ago), and bits 0..14 are all 1 (the fillers).

Step 1 — the hashes for branch B (pc = 0x00006F88)

T1 (4 bits) and T2 (8 bits) see only fillers, so for both values of A they compute the same index and tag: they cannot tell the two cases apart. T3 (16 bits) includes bit 15, and so B maps to two different entries depending on A. gshare with 12–13 history bits is in the same position as T1/T2, which is why it is stuck at about 50 % on B.

Step 2 — the learning sequence

  1. At first no tagged entry is valid, so the provider is T0. The base counter for B keeps flipping, because B's outcome is random from its point of view, and many predictions are wrong.
  2. On a mispredict with provider 0, rule 3 allocates in T1 (the smallest table with u = 0). T1 then becomes the provider, but it has the same problem as T0.
  3. The next mispredicts (provider T1, then T2) allocate in T2 and then in T3. The T3 entry is specific to one value of A, so its counter only ever sees one outcome and quickly becomes strong.
  4. From then on T3 is the provider for B. It is right, and the alternate (T2) is wrong about half the time, so rule 2 sets T3's u bit. Allocation can no longer evict it.

Result in simulation: of 5 882 executions of B, TAGE mispredicts 3 (0.05 %), gshare-4K mispredicts 2 925 (49.7 %). Branch A is random and costs both predictors about 50 %.

9. Design decisions and likely questions

Q: Why LUTRAM and not block RAM?

The specification requires the tables to be read combinationally, so predict finishes in the same cycle. Block RAM only has a synchronous (registered) read. Distributed RAM reads asynchronously, and its dual-port form gives one read/write port and one read-only port, exactly what predict + update need.

Q: Why does each table have two ports?

Predict reads at the address from the hash (port B). Update must read the current entry at the saved address and write the new value (port A, read-modify-write). With separate ports the two never interfere.

Q: Why is there a reset sweep?

LUT-RAM cannot be reset in hardware. After reset, a counter writes the initial value into all 1 024 addresses (1 024 cycles). Without it, a board reset would leave old contents in the tables and runs would not be reproducible.

Q: Why save the metadata instead of recomputing the hash at update time?

The update must modify exactly the entries the prediction used. Saving idx/tag/prov/alt guarantees that, and the update logic needs no hash circuit of its own. The specification also requires it.

Q: Why was upd_pc added to the update interface?

The base table index (pc[11:2]) is not part of tage_meta_t, so the update needs the PC to find the base counter. The metadata struct itself is exactly as specified.

Q: Why rotate f for the tag?

If index and tag were computed from the same bits in the same way, two histories that collide on the index would usually also collide on the tag, and the tag would not help. Rotating gives a different function.

Q: What is the alternate prediction used for?

Only for the u rule. An entry is marked useful when it predicted correctly and the next-best table would have been wrong; that is, it added real information.

Q: Why allocate in the smallest free table?

That is the specification's rule. It uses the shortest additional history that might fix the mispredict, which learns fastest and keeps the long tables free for branches that really need them.

Q: How do you know the design is correct?

It is compared on every branch against an independent reference model, covering outputs and table contents, over 2 million branches. Coverage shows every rule was exercised. 16 deliberately injected bugs were all detected. Two simulators agree.

Q: Why two cycles per branch?

Predict and update are in separate cycles, as the specification requires. With only one branch in flight, the next prediction always sees the updated history, so no speculative history or repair logic is needed. That keeps the design simple.

Q: What limits the clock frequency?

The predict path does hash, table read, tag compare and provider selection in one cycle (11 logic levels). It meets 100 MHz with a small margin. Registering the hash outputs would add margin at the cost of one cycle, without changing behaviour.

Q: Why is TAGE worse than gshare on the random trace?

With random history, every mispredict allocates a new, weak tagged entry, and that entry then overrides the well-trained base counter. Full TAGE designs add extra mechanisms for this (for example use-alt-on-new-allocation and periodic u reset). They are outside this simple specification.

Q: How does this compare to the paper by Matsui et al. (MCSoC 2019)?

It has the same structure as the paper's conventional TAGE: one base table plus four tagged tables, distributed RAM and single-cycle prediction. The paper's TAGE reaches 98 MHz. The paper's pTAGE adds BRAM, pipelining over both clock edges and larger tables (1K entries, 130-bit history) to predict every cycle. That is more complex, and it was intentionally not used here.

10. Limitations

  • One branch every two cycles; a processor front end would need one prediction per cycle (pipelining).
  • No speculative history: branches are predicted and resolved one at a time.
  • Simple replacement policy: a 1-bit u, no periodic u reset, no use-alt-on-new-allocation. This hurts purely random branches.
  • Maximum history 32 branches, so a 40-iteration loop exit cannot be learned.
  • Timing margin at 100 MHz is small (+0.08 ns overall, +0.12 ns on the TAGE path).
  • Verified in simulation and implemented to a bitstream. The bitstream has not yet been run on a physical board.
